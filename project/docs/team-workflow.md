## 2. 第一次打开项目

电脑需要安装 R、RStudio、Git。课程提供的 RStudio 环境也可以使用。

1. 登录自己的 GitHub 账号，进入仓库，点击 **Code**，复制 HTTPS 仓库地址。
2. 在 RStudio 选择 **File > New Project > Version Control > Git**，粘贴地址，选择保存位置，创建项目。若已经克隆过，直接打开现有项目。
3. 在克隆仓库的文件面板进入 **`project/`**，打开 **`project/ids-project.Rproj`**。打开后，RStudio 的工作目录应为该 `project/` 文件夹，能看到 `report.Rmd`、`scripts`、`data` 等文件。
4. 在 **Console** 输入下面两行。安装包可能需要几分钟，安装提示按实际环境处理。

```r
source("scripts/setup.R")
source("scripts/build.R")
```

`setup.R` 用于安装依赖，通常只需首次运行。之后修改内容，可以直接重新运行 `source("scripts/build.R")`。首次安装包需要网络，分析使用仓库中的数据文件。

构建完成后，在文件面板打开 `report.html`、`presentation.html`、`investigation.html`。从 GitHub 下载 HTML 时，使用下载按钮取得实际文件，再用浏览器打开。演示文稿的支持文件也应随项目保留。

如果遇到错误，先保留完整错误文本，检查当前目录和脚本名称，再联系组员解决。不要删除原始数据或逐个改动结果数字来消除报错。

## 3. 每次工作的顺序

1. **Pull**：开始前在 RStudio 的 Git 面板点击 **Pull**，取得组员最新修改。
2. **沟通**：确认本次要编辑的文件，尽量避免两人同时修改同一段报告。
3. **修改并运行**：修改自己的内容，重新运行相关代码；涉及结果或文档时重新构建。
4. **检查差异**：在 Git 面板查看 **Diff**，确认只包含本次工作。原始 CSV、账号凭据和本机设置尤其需要留意。
5. **Commit**：选中应提交的文件，写清修改内容，例如 `Explain the chronological validation split`，然后提交。
6. **Push**：将提交推送到 GitHub，打开网页确认文件已更新。

每位成员使用自己的账号完成真实工作。提交说明应对应实际修改，不回填虚构的分工，不伪造历史，不将自动生成内容登记为其他成员的个人贡献。发现合并冲突时，先与涉及的成员沟通，再共同保留正确内容。

切勿提交密码、访问令牌、`.Renviron` 或其他含凭据的文件。不要用文本编辑器另存原始 `data/SeoulBikeData.csv`，它的字符编码和字节校验值需要保持完整。

## 5. 理解本项目的主要结论

先看 `report.html`，再用 `investigation.html` 查完整代码和中间结果。至少能够回答：

- 8,760 条记录为什么只使用其中 8,465 个运行时段建模？
- 工作日如何定义，关闭时段与零租借量分别代表什么？
- 为什么按时间切分训练、验证和测试？
- 树模型为什么在验证阶段被选中，在测试阶段却输给基线？
- 天气取自同一小时，这对实际提前预测有什么限制？
- 为什么这些相关关系不能直接解释为因果效应？

如发现问题，先修正代码或解释，再重新构建。测试集已经用于报告模型表现；后续改变模型需要新的评估设计，并如实记录变化。
